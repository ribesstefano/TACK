# Fusion context embeddings on the Hugging Face Hub — design

**Date:** 2026-10-06
**Branch:** `fast-surrogates`
**Status:** awaiting review
**Relates to:** `2026-10-03-fusion-surrogates-design.md` (block layout, `CONTEXT_FILES`)

## Goal

Make the PCA-reduced context embedding tables that `tackai/fusion/` depends on distributable,
so that a fresh machine can go from an empty `TACKAI_CACHE` to a working fusion encoder
without the Zenodo archive, the curated CSVs, or a re-run of the three embedding notebooks.

Two deliverables:

1. **`scripts/publish_fusion_context.py`** — stages the tables named in
   `tackai.fusion.context.CONTEXT_FILES` from `TACKAI_CACHE` and uploads them to a new
   Hugging Face dataset repo, `ailab-bio/TACK-fusion-context`.
2. **`FusionData.from_pretrained(...)`** — downloads that repo, installs the files into
   `TACKAI_CACHE`, and returns an encoder-only `FusionData` ready for `encode()` /
   `encode_context()` / `assemble()`.

## Why

`ContextEncoder` reads ten npz files out of `TACKAI_CACHE` and raises `FileNotFoundError` if
any is absent. Those files are produced by `notebooks/context_embeddings.ipynb`,
`notebooks/protein_pooling_comparison.ipynb` and `notebooks/assay_embeddings.ipynb`, each of
which needs the curated CSVs, a GPU-hour of ESM, and a sentence-transformer download. Today
the only way to obtain them is to re-run all three or to be handed the directory.

They are also small — about 1.3 MB for the full set — and they are *inputs* to every fusion
model, not outputs of one. A published ensemble is useless without the exact tables it was
fitted against: `FusionEnsemble._check_layout` exists precisely because a refitted PCA
silently shifts every context block's column offset. Distributing the tables alongside the
ensembles closes that gap.

The legacy pipeline already solves the same problem for its own assets via
`ailab-bio/TACK-cache` and `EnsemblePredictor.from_pretrained`. This design gives the fusion
pipeline the equivalent, following the same idioms.

## Decisions

| Decision | Choice | Rejected alternative |
|---|---|---|
| Hub repo | New dataset repo `ailab-bio/TACK-fusion-context` | A `fusion_context/` prefix inside `ailab-bio/TACK-cache` — couples a fusion PCA refit to the legacy pipeline's cache revision and forces `allow_patterns` filtering on download |
| Repo layout | Flat; filenames are exactly the `CONTEXT_FILES` names | A nested `block/role` tree — would need a name mapping kept in sync with `CONTEXT_FILES` |
| File scope | The 10 `CONTEXT_FILES` entries + a generated `manifest.json` | Also the pre-PCA full-dimension tables (nothing in `tackai/fusion/` reads them) |
| Return value | Encoder-only `FusionData` (`table=None`) | Also publishing `X` / targets / splits — ties the repo to one dataset snapshot |
| Hash mismatch on install | Raise, unless `force_download=True` | Overwrite silently |
| Auto-download | Never from inside `ContextEncoder.table()` | An implicit network call during a kernel fit |

## Architecture

### The Hub artifact

`ailab-bio/TACK-fusion-context`, `repo_type="dataset"`, flat:

```
cell_embeddings_model=sentence-transformer_pooling=mean_pca47.npz
cell_embeddings_model=sentence-transformer_pooling=mean_pca47_model.npz
protein_embeddings_…_layer=18_pooling=lse_window=1022_block=poi_pca51.npz
protein_embeddings_…_layer=18_pooling=lse_window=1022_block=poi_pca51_model.npz
protein_embeddings_…_layer=30_pooling=mean_rm_pc2_window=1022_block=e3_pca7.npz
protein_embeddings_…_layer=30_pooling=mean_rm_pc2_window=1022_block=e3_pca7_model.npz
protein_embeddings_…_layer=18_pooling=lse_window=1022_block=combined_pca52.npz
protein_embeddings_…_layer=18_pooling=lse_window=1022_block=combined_pca52_model.npz
assay_embeddings_vocab=open20_model=all-mpnet-base-v1_pooling=mean_pca8.npz
assay_pca_vocab=open20_model=all-mpnet-base-v1_pooling=mean_pca8.npz
manifest.json
```

The filenames are the `CONTEXT_FILES` values verbatim. `ContextEncoder.table()` builds its
path as `cache_dir / CONTEXT_FILES[block]["table"]`, so installing the repo is a plain copy
with no name mapping — nothing to keep in sync when a PCA width changes and the filenames
change with it.

The `combined` entry is included even though the default `protein_space="per_block"` does not
read it: it is the alternative protein space `ContextEncoder` already supports, and omitting
it would make `protein_space="combined"` fail after a from-Hub install for no visible reason.

### `manifest.json`

Generated by the staging phase, never hand-written:

```json
{
  "format": "tack-fusion-context/v1",
  "created": "2026-10-06",
  "tackai_version": "1.0.0",
  "block_dims": {"e3": 7, "cell": 47, "poi": 51, "assay": 8, "assay_time": 1},
  "combined_dim": 52,
  "models": {
    "cell": "sentence-transformers/all-mpnet-base-v1",
    "assay": "sentence-transformers/all-mpnet-base-v1",
    "poi": "facebook/esm2_t30_150M_UR50D",
    "e3": "facebook/esm2_t30_150M_UR50D"
  },
  "files": {
    "cell_embeddings_…_pca47.npz": {
      "block": "cell", "role": "table", "sha256": "…", "bytes": 88078, "n_keys": 202, "dim": 47
    }
  }
}
```

`block_dims` uses the same key and the same shape that `FusionEnsemble.save` writes, so a hub
manifest can be passed straight to the existing `FusionEnsemble._check_layout` without a
translation step. `n_keys` and `dim` are read out of the npz during staging rather than parsed
from the `_pca47` filename suffix, so a mislabelled file is caught at publish time.

The `models` values come from the `CELL_MODEL` / `ASSAY_MODEL` / `POI_ESM_MODEL` constants in
`context.py`, so the manifest cannot drift from the code that defines them.

### Publishing: `scripts/publish_fusion_context.py`

Two phases, mirroring `scripts/publish_hf.py`, so the staged folder can be inspected before
anything reaches the network:

```bash
python scripts/publish_fusion_context.py stage  [--cache-dir DIR] [--out hf_staging/fusion_context]
python scripts/publish_fusion_context.py upload [--repo-id ailab-bio/TACK-fusion-context] \
                                                [--staged DIR] [--private] [--commit-message MSG]
```

**`stage`**

1. Resolve every `(block, role)` pair of `CONTEXT_FILES` against `--cache-dir` (default
   `get_cache_dir()`). `CONTEXT_FILES` has five entries × two roles = ten distinct paths.
2. If any is missing, print all of them and exit non-zero. Partial publication is refused:
   a repo missing one `pca_model` side file breaks `ContextEncoder.register_sequence` and the
   assay fallback path at inference time, a long way from this script.
3. Open each npz to record `n_keys` and `dim`, and hash each file (sha256, streamed).
4. Write `manifest.json` and copy the ten files into the staging directory.
5. Refuse to write into a staging directory that already exists, as `publish_hf.py` does, so
   stale and fresh files are never mixed.

**`upload`**

1. `HfApi().create_repo(repo_id, repo_type="dataset", exist_ok=True, private=...)`.
2. `upload_folder(folder_path=staged, repo_id=..., repo_type="dataset", commit_message=...)`.
   `upload_folder`, not `upload_large_folder`: the whole set is ~1.3 MB.
3. Print the resolved repo URL and the commit sha.

The script is standalone rather than a third target inside `publish_hf.py`. That script stages
from the repo-root `cache/` tree and deliberately imports nothing from the `tackai` package;
this one must import `CONTEXT_FILES`, the model constants and `get_cache_dir()` from the
package to stay in lockstep with the encoder it is publishing for.

### Downloading: `FusionData.from_pretrained`

```python
DEFAULT_CONTEXT_REPO = "ailab-bio/TACK-fusion-context"   # in tackai/fusion/context.py

@classmethod
def from_pretrained(cls, repo_id: Union[str, Path] = DEFAULT_CONTEXT_REPO, *,
                    revision: Optional[str] = None,
                    token: Optional[str] = None,
                    cache_dir: Optional[Union[str, Path]] = None,
                    force_download: bool = False,
                    protein_space: str = "per_block",
                    featurizer: Optional[MolEncoder] = None,
                    descriptors: Optional[Sequence[str]] = DESCRIPTOR_NAMES) -> "FusionData"
```

Flow:

1. **Resolve the source.** If `Path(repo_id)` exists, use it directly — this is what makes a
   staged directory testable before it is uploaded, and it mirrors
   `FusionEnsemble.from_pretrained`. Otherwise
   `snapshot_download(repo_id=str(repo_id), repo_type="dataset", revision=revision,
   token=token)`, which honours `HF_HOME`. An `ImportError` or a network failure is re-raised
   with the same guidance `ensemble_predictor.py` gives: install `huggingface_hub`, or pass a
   local directory.
2. **Read `manifest.json`** from the resolved source; a missing or unparseable manifest is an
   error naming the source directory.
3. **Install into the cache.** Target is `cache_dir or get_cache_dir()`. For each filename in
   `manifest["files"]`:
   - absent in the target → copy it in;
   - present with a matching sha256 → skip, leaving mtime untouched;
   - present with a different sha256 → raise, naming the file and both hashes, unless
     `force_download=True`, which overwrites.

   Raising on a mismatch is the one opinionated call. A differing table almost always means a
   locally refitted PCA, and overwriting it would change the column widths underneath every
   ensemble already fitted against it — the exact failure `FusionEnsemble._check_layout`
   exists to catch, but surfacing it here, at install time, rather than later as silently
   misaligned predictions.
4. **Build the instance.** `cls(table=None, encoder=ContextEncoder(cache_dir=target,
   protein_space=protein_space), featurizer=featurizer, descriptors=descriptors)`. The
   existing `featurizer`/`descriptors` mutual-exclusion check in `__init__` applies unchanged.
5. **Verify the layout.** Compare the freshly built `self.dims` against
   `manifest["block_dims"]` and raise on any disagreement, in the message style of
   `_check_layout`. The hash check in step 3 cannot catch this on its own: a user whose cache
   already holds a *differently named* table (a different PCA width produces a different
   filename, so no hash is ever compared) would otherwise get a silently mixed cache.

The returned instance is encoder-only. `encode`, `encode_context`, `assemble`,
`assemble_features`, `blocks_indexes`, `dims`, `n_columns`, `context_columns` and
`mol_columns` all work; `X`, `groups`, `smiles`, `target()`, `task_rows()` and `splits()` keep
raising the existing "this FusionData has no table; use from_csv() for training data".

`DEFAULT_CONTEXT_REPO` is defined in `context.py`, not `data.py`: it is a property of the
context tables, which `ContextEncoder` owns. It is re-exported from `tackai.fusion`.

## Data flow

```
publishing                              consuming
----------                              ---------
TACKAI_CACHE (producer's)               ailab-bio/TACK-fusion-context
   │ stage: hash, read dims, copy          │ snapshot_download (honours HF_HOME)
   ▼                                       ▼
hf_staging/fusion_context/              HF_HOME snapshot
   │ upload_folder                         │ install: sha256 compare, copy
   ▼                                       ▼
ailab-bio/TACK-fusion-context           TACKAI_CACHE (consumer's)
                                           │
                                           ▼
                                        ContextEncoder → FusionData → FusionEnsemble
```

The HF snapshot is not the working directory: files are copied out of it into `TACKAI_CACHE`,
so the cache stays a single self-contained directory that works offline and that
`ContextEncoder(cache_dir=...)` can be pointed at directly, as it is today.

## Error handling

| Condition | Behaviour |
|---|---|
| Staging: a `CONTEXT_FILES` entry is missing from the cache | List every missing file, exit non-zero. No partial repo. |
| Staging: the output directory already exists | Refuse, as `publish_hf.py` does. |
| Upload: not authenticated / no write access | Propagate the `huggingface_hub` error unchanged; the token guidance already lives in `.env.example`. |
| `from_pretrained`: `huggingface_hub` not installed | `ImportError` re-raised with "install huggingface_hub, or pass a local directory". |
| `from_pretrained`: repo id not found / offline | Propagate, with the local-directory suggestion appended. |
| `from_pretrained`: no `manifest.json` in the source | `FileNotFoundError` naming the resolved source directory. |
| Install: cached file differs by sha256 | `ValueError` naming the file and both hashes; `force_download=True` overwrites. |
| Install: target directory not writable | Propagate the `OSError`. `get_cache_dir()`'s own tempdir fallback already covers the common case. |
| Post-install: `dims` disagree with `block_dims` | `ValueError` in `_check_layout`'s message style, telling the user their cache mixes tables from two PCA fits. |

## Testing

New `test/test_fusion_hub.py`. Nothing here needs the network or the real cache, so nothing is
marked `requires_cache`; everything runs on the existing `fake_cache` fixture, whose files
already carry the real names and the real widths.

**Prerequisite fixture change.** `fake_cache` currently writes **nine** files: it has a PCA
side file for `cell`, `poi`, `e3` and `assay`, but not for `combined` — no test reads it, so
its absence has never mattered. Staging resolves all ten `CONTEXT_FILES` paths and refuses a
partial set, so the fixture must gain
`_write_pca_model(cache / COMBINED_FILE.replace(".npz", "_model.npz"), 640, 52, 10)`. The
addition is inert for every existing test: nothing loads that file today, and the real cache
already ships it.

1. **Stage round-trip.** Stage from `fake_cache` into `tmp_path`: the ten files plus
   `manifest.json` exist; every recorded sha256 matches the staged bytes; `block_dims` matches
   the fixture's widths (cell 47, poi 51, e3 7, assay 8, assay_time 1) and `combined_dim` is 52.
2. **Stage refuses a partial set.** Delete one `pca_model` from the fake cache; staging raises
   and the message names that file.
3. **Stage refuses an existing output directory.**
4. **Install from a local directory.** `from_pretrained(<staged dir>, cache_dir=<empty tmp>)`
   copies the ten files in, returns a `FusionData` whose `dims` and `blocks_indexes` match the
   fixture, encodes a `tiny_records` entry through `encode_context`, and still raises on `X`.
5. **Second call is a no-op.** Record mtimes, call again, assert unchanged and no error.
6. **Tampered cache file.** Rewrite one cached npz with different contents: `from_pretrained`
   raises naming it; with `force_download=True` it is overwritten and the hash matches again.
7. **Repo-id branch.** Monkeypatch `huggingface_hub.snapshot_download` to return the staged
   directory; `from_pretrained("ailab-bio/TACK-fusion-context", cache_dir=…)` behaves as (4),
   and the patched call received `repo_type="dataset"`.
8. **Layout mismatch.** Hand-edit the staged manifest's `block_dims["cell"]` to 48; install
   into an empty cache raises the layout error.
9. **`protein_space="combined"`** works after a from-Hub install, since the combined table is
   published.

`OMP_NUM_THREADS=1 pytest test/test_fusion_hub.py` must pass, and the full suite must stay
green.

## Documentation

- `.env.example`: a line naming `ailab-bio/TACK-fusion-context` beside the existing
  `TACK-ensembles` / `TACK-cache` comment, noting it is public and needs no token.
- `docs/`: a short "populate the cache from the Hub" section on the fusion pages, with the
  two-line usage.
- `tackai/fusion/context.py` module docstring: it currently states the tables are produced by
  three notebooks and live in `TACKAI_CACHE`. Per CLAUDE.md, this docstring carries the design
  rationale, so it gains a sentence saying they can also be fetched from the Hub, and *why*
  the fetch never happens implicitly inside `table()`.
- `tackai/fusion/__init__.py`: export `DEFAULT_CONTEXT_REPO`.

## Non-goals

- Publishing the pre-PCA full-dimension tables. Nothing in `tackai/fusion/` reads them; a user
  refitting a PCA is re-running the notebooks anyway.
- Publishing the molecular caches (`morgan_fp_*.npz`, `rdkit_descriptors.npz`). `MolEncoder`
  featurises on the fly by design and never reads a cache.
- Auto-downloading from inside `ContextEncoder.table()`. An implicit network call in the
  middle of a kernel fit is worse than the clear `FileNotFoundError` that exists today.
- A `tack` CLI subcommand. The fusion pipeline is a Python API driven from notebooks; the
  publish script is a maintainer tool.
- Uploading fitted fusion ensembles. `FusionEnsemble.save` / `from_pretrained` already cover
  that and are unchanged here.
